# 通知勿扰与未读

状态：软件已接入，主机测试和组合固件构建通过；尚未刷写验收。
是否收到手机端主动消息、计划任务或其他会话消息，仍需真实 Muse 事件证明。

默认启用自动通知，不启用静音时段。通知设置与免手持开关独立：设置保存在
`muse_notice/policy` 的版本化九字节 NVS 记录中，免手持仍每次开机关闭。
默认时间模板是 UTC+8 的 22:00–08:00，只有明确打开勿扰后才生效。
时段左闭右开、支持跨夜；相同起止时间表示全天。时区使用固定分钟偏移，
不会自动处理夏令时。启用时段而设备尚未同步时间，或者设置损坏/读取失败时，
自动通知保持静音；重新保存合法设置可修复。无效保存或 NVS 提交失败不会更新运行策略。

设备 Sound 页可切换 Mute notices / Quiet hours，查看未读数量并选择
Read next notice。配置网页可编辑时段、时区、自动通知静音并逐条读取。
USB `notice.read` 也只请求读取一条。网页沿用配置热点范围和 CSRF 校验，
请求只接受规定字段和类型；202 代表排队，不代表已播放。

静音、勿扰或关闭扬声器/零音量期间收到的通知保留为未读。
时段结束或恢复扬声器后不会集中补播旧消息；只有之后新到的通知可自动播报。
用户主动读取可以越过通知勿扰，但仍要求扬声器打开且音量大于零。
同一读取请求只处理一条，反复提交未处理的请求会合并，不自动开启续听。
停止操作撤销等待中的读取，使排队通知保留未读。

收件箱最多四条，包含正在处理的一条；未读正文只在 RAM，重启清空。
静音未读不会阻塞之后新通知的自动播报或免手持等待。
通知开始处理时保留一个容量位置，只有完整 TTS 成功、PCM 写入成功并确认
输出排空后才从未读移除。合成部分失败、输出失败、排空失败、超时、取消或
跨入勿扰时，通知回到未读，绝不自动重试。用户之后明确读取可从头重新播报。
不支持输出排空的板型无法确认完成，保留未读；StackChan/CoreS3 已有排空实现，
仍需实际硬件测量。合成 HTTP 成功或拿到部分音频都不是播放完成证明。

StackChan 的通知正文已改为最多 16,384 字节的完整 UTF-8 文本，使用 PSRAM 并分段朗读；
没有 PSRAM 的板型最多 700 字节，均拒绝超限消息而不截断。网页和 Sound 页显示未接收
计数及最近原因。完整存储不证明 Muse 真正投递长任务结果，仍需实际事件验收。
队列满会拒收，没有已验证的服务端重放保证。
这些限制、真实任务事件和手机事件、真实静音切换/触摸停止、长时间稳定性均需继续验收。

测试执行生产策略、队列、包装层及播放函数，使用假 NVS、时钟和音频设备，
覆盖保存失败/损坏记录、全天与跨夜边界、时区、未同步时间、容量预留、停止、
部分合成和排空失败。网页 JavaScript 和真实 cJSON 的 HTTP 处理函数也有测试。
这些结果不替代实际扬声器、设备触摸或 Muse 事件投递证据。
