# 完整通知文本与分段朗读

状态：软件开发/验证中，尚未刷写。不等于普通对话长回复或真实任务事件已验收。

StackChan 的通知收件箱使用按需 PSRAM 分配，保存最多 16,384 字节的完整 UTF-8 正文。
取出时向唯一语音任务转移只读借用，不在语音栈上分配大文本，也不再复制一份完整正文。
四条容量包含正在播放的一条，最大正文总量约 64 KiB；内部 RAM 只保留指针和元数据。
无 PSRAM 板型维持 700 字节上限，接口明确报告实际容量。

正文按不超过 700 字节的完整码点分段，逐段调用 TTS、写入并排空音频。
只在第一段提示音和表情修饰，所有分段都尊重停止、按键接管和通知勿扰。
字幕显示当前分段开头；不声称逐字对齐。合成前为等待状态，写入实际 PCM 后才为说话状态。
分段共享同一完整通知；全部成功后才移出未读。中途失败或取消保留整个正文，绝不自动重试。
用户之后主动读取会从头开始，可能重读此前已听到的分段。

一次通知有二十分钟总处理期限；每段原有四十五秒限制也保留，取较早者。
长正文会调用多次豆包，模型/网络错误不被当作完整播放。
超限、无效 UTF-8、分配失败或队列满会拒收并显示计数/原因，不以截断前缀冒充完整结果。
正常重复消息只去重，不增加错误计数。未读和错误计数只在本次启动的内存中。

这只改善官方事件通道已经送达设备的通知。是否真正投递手机主动消息或任务结果仍未知。
普通问答后端的文字缓存与本地 TTS 长度限制仍需另外处理，不能因通知支持分段就宣称
所有长回复已完整保留。真实长音频、内存峰值、取消时延和服务端事件还需要硬件验收。
