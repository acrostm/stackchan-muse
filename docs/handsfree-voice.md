# 免手持唤醒、VAD 与续听

状态：策略核心与官方 ESP-SR 适配器已有主机测试，官方模型已完成真实固件链接；
自动录音已接入单一语音任务，USB 命令可显式开启；尚未刷写或执行真实唤醒推理。
不能据此宣称设备已经通过免手持对话验收。

`muse_handsfree_core.[ch]` 仅消费唤醒结果与新鲜 VAD 语音样本时长，不读取音频，
不把能量阈值冒充语音分类。已接入官方 ESP-SR 2.6.0 的 WakeNet/VAD 接口，使用单一语音任务持有识别器。
实际模型初始化、资源测量与推理仍需硬件验证。

策略默认关闭。开启后先清空旧音频并冷却；模型检测到唤醒后只开始本地缓冲，
未积累至少 300 毫秒有效语音不允许提交。无语音五秒丢弃，短语音后的静默也丢弃，
有效语音后静默 800 毫秒结束，录音上限十五秒。语音时长依据实际 VAD 样本，
不能因 CPU 阻塞或延迟调用而累计更多语音；重复时刻的分类结果不重复计数。

播放/等待期间禁止新唤醒，模型状态与旧 PCM 缓存必须清理。只有实际本地轮次与
播放完成事件能开启续听；HTTP 成功、开始合成或收到文字不算播放完成。
续听在 600 毫秒冷却后最多八秒，超时回到需要唤醒词的待机。
取消、关闭、异常时钟或严重音频间隔使当前代次失效；旧完成事件不能重新打开麦克风。
物理 PTT 仍保留原来的两秒误触保护，不能用自动录音来源绕过物理取消结果。

已锁定官方 ESP-SR 2.6.0。官方清单含 `wn9_histackchan_tts3`（Hi, Stack Chan），
并未把它当作 Muse 唤醒词。最终默认词、检出率和误唤醒需要实际模型与桌面测试。
官方清单允许加载外部模型，但不代表当前项目已有自定义 Muse 模型。

- [官方唤醒模型列表](https://github.com/espressif/esp-sr/blob/master/wakeword_list.md)。
- [官方 AFE 输入与接口说明](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/audio_front_end/README.html)。

依赖、许可与三个模型资产已锁定。新增 model 分区位于 0x830000，大小 2 MiB，
不移动原有 NVS、OTA 或生产数据分区。构建后检查源资产及打包镜像；设备初始化前
核对模型表、连续偏移、长度与 SHA-256，再检查可用映射页和内存。资源检查不能
保证并发分配永不失败。`sr.probe` 仅在语音任务中初始化、报告内存并释放模型，
不读取麦克风、不推理、不上传、不移动舵机。

运行时 `voice.handsfree=on` 开启，`voice.handsfree=off` 关闭并取消当前语音。
每次启动默认关闭，不持久化开关。录音先缓存在 PSRAM，策略认可有效语音并
静默结束后才开始网络轮次；短声音、取消、关闭、读音频失败、断网或按键接管
均丢弃。自动录音不进入延迟重试队列，按键继续走独立的两秒保护路径。
设置麦克风监视、等待旧手动录音、通知或服务未就绪时禁用新唤醒。
显式开启后屏幕自动休眠不等于关闭麦克风，唤醒成功会点亮屏幕；需要停止
本地监听时使用关闭命令，重启也会恢复关闭。电池续航影响尚需实测。

真实续听暂未开启：现有音频写入返回不代表扬声器 DMA 已排空。只有后续可靠的
播放完成事件才可启动策略核心中的续听窗口。尚需网页/屏幕开关与明确静音反馈。

尚需：硬件模型初始化/推理与分区迁移验证；续听与播放器排空关联；
三十次唤醒、两小时背景音、二十轮对话，以及原计划并发和长时间稳定性验收。
